# HowMuch iOS

A YNAB-styled transaction ledger, editable monthly Plan, and reports companion.

API dependency:

- `GET/POST/PUT/DELETE /v1/plans/{id}/transactions[/{txid}]`
- `GET /v1/plans/{id}/accounts`, `/categories`, `/payees`, `/settings`, `/account_preferences`
- `POST /v1/plans/{id}/accounts`
- `PUT /v1/plans/{id}/account_preferences`
- `GET /v1/plans/{id}/months/{YYYY-MM}`
- `PATCH /v1/plans/{id}/months/{YYYY-MM}/categories/{categoryId}`
- `GET /v1/plans/{id}/scheduled_transactions`

On first authenticated launch, the app discovers and saves the server's only
accessible plan. It retains an existing selected plan and never guesses when a
server exposes more than one; choose the plan explicitly in Connection.
- `GET /api/reports/spending-breakdown`
- `GET /api/reports/income-vs-spending`
- `GET /api/reports/net-worth`
- `GET /api/reports/age-of-money`
- `GET /api/reports/rewards`
- `GET/POST /api/import/rewards-tracker`
- `GET /api/auth/status`, `POST /api/auth/token`, `POST /api/auth/logout`

The app stays transaction-led: accounts, registers, capture, and reflection sit alongside an editable monthly Plan. It does not expose YNAB credit-card payment workflows.

## App Structure

`apps/ios/HowMuch.xcodeproj` contains a SwiftUI app (iOS 26+) with a Liquid Glass tab bar of Accounts, Rewards, and Reflect on iPhone, a trailing **Add Transaction** button on that bar, a floating **Assistant** (speech bubble with a plus) above Add, and a connection sheet. iPad regular width puts Plan and Assistant in the sidebar and keeps the floating plus.

- `Accounts`: grouped account list. A trailing **New Account** plus opens a sheet for name, type (Budget vs Tracking), icon, and current balance or amount owed, then `POST`s the account. Long-press a row (or the register title) for **Edit Account** — name, type, and icon; `PATCH`s the account and leaves balances alone. Your groups (Favourites and custom collections) sit above a quieter By type index (Cash / Credit / Tracking / Closed). Sections collapse, show group totals, and three shortcuts (New, Scheduled, All). New is the unapproved inbox with Approve all. Each account opens its register, whose top-right menu covers Edit Account, favourites, filters, groups, and reconcile. Trailing **More** (ellipsis) opens Plan, Assistant, and Connection settings. **Add Transaction** is the trailing tab-bar plus (not a fourth tab) that opens the manual form and does not change the selected tab. **Assistant** is the floating speech-bubble-plus above Add and opens the same More Assistant overlay. Plan still opens from More.
- `Register`: date-grouped transactions with the account balance, a last-reconciled subtitle, search, overflow-menu filters for new, uncleared, and uncategorised rows, one-tap uncleared/cleared badges, locked reconciled badges, flag bars, memo chips, and split/transfer labels. Swipe a row right to approve an unapproved transaction, or left to delete (the confirm names a linked transfer or a reconciled row only when those apply). Tapping a row opens the edit form, where Cleared is a switch (Save writes it only if the switch moved, so an untouched editor cannot clobber a register tap). Reconciled rows stay locked. Save asks for confirmation only when this row or a loaded linked transfer is reconciled and the amount, account, date, transfer destination, or a split transfer line changed. Long-pressing offers Edit, Duplicate for Today, and Delete. Duplicate opens the capture sheet prefilled from that transaction with the group Save button one tap away (splits excluded — the app's write request carries no subtransactions). Long-pressing the app icon offers an Add Expense quick action straight into the capture sheet. Whenever the visible rows are a deliberate slice (a search, a menu filter, or a report drill-down), a Money In / Money Out / Net summary card appears above them, as in the web register header. Category drill-downs match split lines too, so a category filter finds transactions whose subtransactions carry it.
- `Rewards`: imported Rewards Tracker cards against the HowMuch ledger. Filter chips cover All Time (the default), account scope, and grouping by Flag, Payee, Category, or Memo. Headlines show qualifying spend and value, plus miles or cashback when those totals are above zero. Cashback tiles sit above miles tiles. An empty range points at Connection settings → Rewards import. Rewards is not a Reflect card.
- `Plan`: a YNAB-style monthly plan reached from **More → Plan** on iPhone, or the iPad sidebar. A `‹ June 2026 ›` month stepper, Ready to assign, Assigned, and Activity totals, collapsible category groups, and each category's Assigned, Activity, Available, and target progress. Rows drill into that category's register for the month; assignment and target controls open editing sheets; bookkeeping groups sit behind a toggle. Target edits are HowMuch-local overlays and can restore the imported target.
- `Scheduled Transactions`: a date-grouped schedule from the Accounts tab. Rows retain their next date, inflow/outflow amount, payee or transfer destination, account, category or split summary, and recurrence. Add, edit, and delete work through HowMuch-owned overlays, while the imported YNAB source remains intact; pull to refresh reloads the effective schedule. The editor can convert a schedule to a split, add, edit, and remove split lines (minimum two), and set each line's signed amount, payee or transfer, category, and memo; the parent amount is always the exact line total. `Enter Now` confirms one selected occurrence, posts it into today's register, then reloads the schedule, register, account, and plan state.
- `Add Transaction` (trailing tab-bar plus): the manual form `.sheet` / large. Tapping Add does not change the selected tab. There is no tap-and-hold menu on this control.
- `Add Transactions` (Assistant conversation): conversation-first Quick Add (`Close | Add Transactions`, no toolbar expand). One chronological transcript and a keyboard-safe composer dock; compact outlined rectangular group Save is the only commit. Plus stays reachable during a model turn so Enter manually can stop that work; Photo Library, Camera, and Paste stay blocked while busy. **Done** applies a local preview. There is no Open in Assistant handoff from Quick Add. A visible account register on the current destination uses that account; overview, Rewards, Reflect, Plan, Assistant, and the Home Screen Add Expense shortcut use the last-used open account.
- `Assistant`: opened from the floating speech-bubble-plus above Add, from **More → Assistant** on iPhone, or the iPad sidebar. Destination for the same capture session, recent unfinished conversations, a Today recorded-spending brief, and read-only ledger questions. Questions use report totals, not the paged register. They cannot change saved transactions.
- `Reflect`: a root tab. Cards for Spending Breakdown (stacked share bar, top categories), Net Worth (assets/debts, column trend), Income vs Spending (paired columns), and Age of Money. Each card opens a detail screen whose filters sit in one chip row: a date-range menu (choose a month with the `‹ June 2026 ›` stepper, a named preset such as This Month through All Time, or custom from/to dates), a grouping menu on reports that bucket by period (By week / By month, and By year on Income vs Spending), account scoping on every report, and category scoping on Spending and Income vs Spending (chip-triggered multi-select sheets, with Uncategorised available as a pseudo-category). Spending Breakdown excludes bookkeeping ("quiet") groups by default behind a persisted Include toggle with an excluded-amount note, buckets categories under group subtotal headers, and shows largest line, average transaction, and per-category transaction counts; category rows drill into a filtered register that honours the account scope. Net Worth adds a change-on-previous-period headline and a per-period history with deltas. Income vs Spending defaults to Year to Date and adds range totals with a savings rate, plus cumulative net per period. Age of Money always measures the full history (the server replays income lots from `from`) and reports matched/unmatched spending per period, with a note when pre-income spending is excluded from the weighted age.
- `Connection` (**More → Connection settings** on Accounts, Rewards, Reflect, Plan, or Assistant): defaults new installs to `https://howmuch.tk.sg` (and migrates the two former defaults, `http://127.0.0.1:8787` and `https://howmuch.soon.sg`, while preserving custom URLs), stores the base URL and username in `UserDefaults`, and keeps the opaque native bearer token in Keychain. HTTP is accepted only for this device or this LAN. Before password sign-in it checks the unauthenticated auth status. If the server still needs its first owner, the app explains that setup must be completed in the same-origin website and opens the configured HTTPS site in the system browser; iOS never asks for or stores the bootstrap token. The authenticated plan is selected automatically, and passwords are never persisted. A Debug build can receive a production-only connection bootstrap once from its launch environment; the opaque token still goes only to Keychain and is never bundled or logged.

Visual language follows YNAB: warm cream canvas, white rounded cards, blurple accent, lime inflow highlight, ledger red/green amounts, monospaced digits. Money is felt as well as seen: keypad keys tick haptically (light for digits, firmer for operators), flipping Outflow/Inflow gives a selection tap, a successful save lands with a success haptic alongside the toast (which carries a check or warning glyph), and money figures (the capture amount, register balance and filter totals, account and group balances, Plan totals, and Reflect headlines) roll digit-by-digit via numeric text transitions.

Design tokens live in `Support/Theme.swift`. `Theme.Radius` sets continuous corner radii (8 inset, 12 control, 16 card, 28 panel; Rewards rows keep their agreed 18pt). `Theme.Motion` sets the shared animations: `standard` for user-driven changes such as expanding a group, toggling a filter or stepping a month; `arrive` for loaded data, toasts, and new rows; `chart` for bars, meters, and sparklines growing into place; and `press` for touch-down feedback. Tappable cards use the `.pressable` button style, which sinks slightly under the finger, and rows inside a card use `.cardRow`, which highlights in place. Charts grow in on first appearance and animate between data sets. Under Reduce Motion they appear finished and cards do not scale. Collapsing a group folds its card up under the header. Status glyphs morph with symbol transitions rather than swapping views, and report screens fade new data in without flashing an error when a filter change cancels the previous request.

Chrome follows iOS 26 Liquid Glass: native glass tab and navigation bars (the tab bar minimises on scroll), a glass keypad panel, a compact outlined rectangular group Save, and a glass toast — content cards stay opaque per the glass guidelines.

Capture never fails for want of a connection: when a new transaction provably cannot reach the server (connection-level failures only — timeouts and server rejections still surface, because the server might already have committed the write), it is queued in a persisted outbox, announced as "Saved offline", and replayed oldest-first on the next refresh against the same connection it was captured on. The Accounts tab shows the queue with per-item sync errors, a Sync Now button (server-rejected entries only retry manually), and a confirmed discard. Offline edits are not queued, so a stale update can never clobber changes made elsewhere.

State lives in one observable `AppModel` with independent load phases per surface (reference data, ledger, reports), so a failure in one tab does not bleed into the others. Dates use the local calendar (a transaction entered before 8am SGT must not land on yesterday's GMT date). Bookkeeping category groups from the YNAB import ("Hidden Categories", "Non-Personal", inflows) are demoted in pickers and reports via the same quiet-group heuristic as the web app. The last-used account (updated only after a successful save), last Quick Add chat/Manual preference, and the spending report's include-bookkeeping toggle are remembered across launches.

## Validation

Use `scripts/ios-xcodebuild.sh` from the repo root. It implements the [iOS validation contract](AGENTS.md): one owner per checkout, a pinned iOS 26+ simulator UDID, `build/xcode/DerivedData-simulator`, `-jobs 2 COMPILER_INDEX_STORE_ENABLE=NO`, and timestamped logs under `build/xcode/logs`. Rebuild after source changes and do not run tests from a failed build. Choose tests and representative UI states relevant to the change.

```sh
scripts/ios-xcodebuild.sh doctor
scripts/ios-xcodebuild.sh test
```

`CaptureInterpreterTests.testLiveFoundationModelsCoffeeAddUpdateAndTodayQuery` is an opt-in on-device Foundation Models regression. The normal native suite skips it. On a Mac where `SystemLanguageModel` is available, put `HOWMUCH_LIVE_MODEL_VERIFY=1` in the test process (`TEST_RUNNER_HOWMUCH_LIVE_MODEL_VERIFY=1` for `xcodebuild`) and run that method. It uses the production `.foundationModels` backend against a local fixture session only — no API, no ledger save — and keeps each fixture input plus raw/mapped extraction as `XCTAttachment` evidence. Linux cannot run native tests or the live model.

Local unsigned builds/tests use the intended worktree; they do not require signing secrets, committed/pushed code, or updating to `main`. Simulator installation/launch is local validation, not physical-device distribution.

For explicitly authorized signed publication to a registered iPhone, follow the [Speedflight runbook](../../docs/speedflight.md). `scripts/speedflight.sh` signs, exports, and uploads in one invocation; do not use it as a local build check. Bump `CURRENT_PROJECT_VERSION` in the Xcode project before each cut; the install page URL does not change.
