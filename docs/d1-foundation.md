# D1 Foundation

D1 databases apply `apps/api/d1-migrations/0001_initial.sql` through `0018_account_month_balances.sql`. The first defines the ledger, import, scheduler/receipt, audit, guarded-write, and auth foundation; migrations 0002–0009 add password auth and the reviewed import/planning/scheduling/reconciliation extensions; 0010 enforces unique live import IDs; 0011 stores revocable, user-scoped personal API token fingerprints; 0012 stores synced account-organisation preferences; 0013 splits a leading account icon from the name; 0014 backfills leftover leading name emojis that 0013 skipped (variation selectors and surrounding spaces); 0015 stores Rewards Tracker export snapshots and cards; 0016 adds query indexes for transfer-graph lookups, live register paging, reconciled-date probes, and live payee lists; 0017 materialises the YNAB month activity baseline into `ynab_source_month_activity` so a month view reads one month instead of scanning every raw transaction object in the plan; and 0018 adds `account_month_balances`, a per-account, per-month net-change aggregate that serves the net-worth report, plus `report_cache`, a small knowledge-keyed cache for age of money. Migration 0018 rebuilds the aggregate from history and installs three triggers on `transactions` that recompute the affected account-month after any insert, delete, or balance-changing update, so every write path maintains it without code changes. Any future migration that rebuilds the `transactions` table must recreate those triggers. Trailing emojis stay on the name. Imported YNAB objects remain read-only. Effective projections combine the source with guarded local changes and are not written back to YNAB. Reconciliation is a post-cutover HowMuch write and must not be followed by a YNAB re-import. This is a focused migration surface, not a claim of full YNAB feature parity.

The account/transfer-payee relationship deliberately uses ordered creation plus ownership triggers rather than immediate cyclic foreign keys. Ledger sequence triggers and unique indexes preserve deterministic ordering. D1 writes remain complete atomic batches with write-version, receipt, assertion, and lease checks.

Wrangler binds the reviewed `howmuch-production` and `howmuch-preview` D1 databases. A target starts clean, then the validated offline YNAB bootstrap may load the verified ledger, provenance, and source mirror; never use an ad-hoc database copy.
