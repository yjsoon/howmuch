# D1 Foundation

D1 databases apply `apps/api/d1-migrations/0001_initial.sql` through `0009_account_reconciliation_assertions.sql`. The first defines the ledger, import, scheduler/receipt, audit, guarded-write, and auth foundation; the second activates first-party password credentials, one-time setup, and login throttling; the third permits ID-distinct YNAB payee IDs with the same display name; the fourth stores a per-object, lossless YNAB source mirror; the fifth and sixth store HowMuch-owned assignment and target overlays; the seventh stores HowMuch-local schedules plus overlays and tombstones for imported schedules; the eighth prevents stale schedule merges from overwriting concurrent edits; and the ninth asserts an exact account-reconciliation snapshot inside its guarded batch. Imported YNAB objects remain read-only. Effective projections combine the source with guarded local changes and are not written back to YNAB. Reconciliation is a post-cutover HowMuch write and must not be followed by a YNAB re-import. This is a focused migration surface, not a claim of full YNAB feature parity.

The account/transfer-payee relationship deliberately uses ordered creation plus ownership triggers rather than immediate cyclic foreign keys. Ledger sequence triggers and unique indexes preserve deterministic ordering. D1 writes remain complete atomic batches with write-version, receipt, assertion, and lease checks.

Wrangler binds the reviewed `howmuch-production` and `howmuch-preview` D1 databases. A target starts clean, then the validated offline YNAB bootstrap may load the verified ledger, provenance, and source mirror; never use an ad-hoc database copy.
